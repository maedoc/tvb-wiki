The Connectome File Format Library (cfflib) is a pure Python library designed for multi-modal connectome data and metadata management and integration. Developed at the École Polytechnique Fédérale de Lausanne (EPFL) and the Hospital Center and University of Lausanne (UNIL-CHUV) in Switzerland, cfflib provides a unified framework for packaging and organizing diverse neuroimaging and connectivity data formats within a single container file. The library forms a core component of the Connectome Mapping Toolkit (CMTK), an open-source software suite for constructing and analyzing brain connectivity networks from diffusion MRI tractography data. By abstracting the complexities of various data formats and providing robust metadata tagging capabilities, cfflib enables researchers to organize multi-scale, multi-modal connectome datasets in a standardized and reproducible manner.

## Motivation and Context

The field of connectomics generates highly heterogeneous datasets spanning multiple modalities—diffusion-weighted MRI for structural connectivity, functional MRI and EEG/MEG for functional dynamics, surface meshes for cortical geometry, and fiber tractography data for white matter pathways. Managing these diverse data types alongside their associated metadata (acquisition parameters, preprocessing pipelines, subject demographics) presents a significant organizational challenge. Early connectome research often stored different data types in separate files with ad-hoc naming conventions, making it difficult to track which elements belonged to the same dataset or to reproduce the exact processing pipeline that generated particular outputs.

CFFlib addresses this problem by defining the Connectome File Format (CFF), a container format that can encapsulate multiple data types within a single archive while preserving rich metadata annotations. The format was designed to support the complete provenance of connectome processing pipelines—a researcher can store not only the final connectivity matrices but also the intermediate tractography files, surface meshes, volumetric images, and the analysis scripts that generated the results. This approach substantially improves reproducibility and facilitates data sharing across the connectomics community, particularly relevant for large-scale projects like the [[human-connectome-project]] that generate multi-modal datasets requiring systematic organization.

## Technical Implementation

The Connectome File Format organizes data into several specialized object types, each designed to handle specific categories of connectome-related information. The **CNetwork** object stores graph-based representations of brain connectivity—typically weighted adjacency matrices derived from tractography or statistical dependencies between regional timeseries—using established formats including GraphML, GEXF, and NetworkX pickle files. **CSurface** objects handle cortical surface mesh data in GIFTI format, preserving vertex coordinates, faces, and optional vertex-wise scalar data such as curvature or thickness measures. **CVolume** objects accommodate volumetric neuroimaging data in NIfTI-1 format, commonly used for anatomical MR images, statistical maps, and parcellation volumes. **CTrack** objects store deterministic or probabilistic fiber tractography results in TrackVis (.trk) format, maintaining streamline coordinates along with associated metadata such as seed regions and tracking parameters.

Beyond these primary neuroimaging data types, cfflib supports several auxiliary object categories. **CTimeserie** objects store temporal data—including fMRI timeseries, EEG/MEG recordings, or simulated neural activity—using HDF5 or NumPy array formats. **CMetadata** objects encode provenance information using the Connectome Markup Language, an XML-based schema for describing acquisition protocols, processing pipelines, and analysis parameters. **CData** objects provide a flexible container for tabular data, JSON configuration files, CSV spreadsheets, and other structured data that may not fit neatly into the primary categories. The library relies on [[nibabel]] for low-level neuroimaging format I/O operations and leverages [[numpy]] along with the Python standard library for general-purpose data handling.

## Key Features

One of cfflib's distinguishing features is its flexible metadata annotation system. Users can attach arbitrary metadata as tags or structured properties to any connectome object, enabling comprehensive documentation of experimental conditions, processing steps, and analysis configurations. This metadata persists through the CFF file and can bequeried programmatically, facilitating automated pipeline selection and quality control. The library also supports embedding processing and analysis scripts directly within CFF containers through **CScript** objects, ensuring that the exact code used to generate connectivity matrices is preserved alongside the results—critical for reproducible connectome research.

The CFF format supports both single-subject and multi-subject datasets, with hierarchical organization enabling researchers to group related data elements. For group studies, multiple subjects' connectivity networks can be stored within a single CFF file alongside population-level metadata such as group assignments or clinical identifiers. The format is extensible, allowing developers to introduce new object types without breaking backward compatibility with existing CFF files.

## Relationship to TVB

While CFFlib was developed primarily for organizing empirical connectome data from neuroimaging studies, its role in the broader [[whole-brain-modeling]] ecosystem merits consideration. The structural connectivity matrices stored in CFF files—whether derived from [[diffusion-imaging]] tractography or [[structural-connectivity]] analyses—serve as the anatomical scaffold for [[the-virtual-brain]] and other whole-brain simulators. TVB's native connectivity format accepts parcellated structural connectivity matrices in various formats, which can be generated from CFF-organized tractography data using tools like the Connectome Mapper pipeline. Researchers building personalized brain models using TVB often begin with CFF-formatted datasets containing the diffusion MRI-derived connectivity scaffolds, which are then imported into TVB's [[tvb-library]] for simulation. The metadata preservation capabilities of CFFlib prove particularly valuable in clinical applications of [[personalized-brain-modeling]], where documentation of the precise connectivity extraction pipeline is essential for interpreting simulation results and ensuring reproducibility across studies.
