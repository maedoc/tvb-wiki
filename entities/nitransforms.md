# NiTransforms

## Overview

NiTransforms is a Python library for handling spatial transforms in [[neuroimaging]] data [@nitransforms-joss]. Developed and maintained by the NiPy community, it provides a unified interface for reading, writing, and applying transformation matrices generated by the most popular neuroimaging software packages—including AFNI, FSL, FreeSurfer, ITK/ANTs, and SPM. The library addresses a critical interoperability problem in the neuroimaging ecosystem: each software tool uses distinct file formats and coordinate conventions for representing spatial transformations, which historically has made it difficult to combine tools in processing pipelines without losing accuracy or requiring manual conversion.

## Motivation and Context

Image registration—the process of aligning two or more images to a common coordinate space—is a foundational operation in nearly all neuroimaging pipelines. Whether aligning functional MRI scans to anatomical templates, registering diffusion-weighted images to T1-weighted volumes, or transforming data from native scanner space to standard stereotactic spaces like [[mni-space]], spatial transformations are essential for any analysis that combines data across subjects, sessions, or modalities. The proliferation of registration algorithms across different software packages has resulted in a fragmented landscape of data structures and file formats. An affine transformation generated by FSL's FLIRT cannot be directly applied in AFNI without conversion, and FreeSurfer's LTA format uses coordinate conventions that differ from ITK's HDF5 format. This fragmentation endangers [[reproducibility]] and makes it cumbersome to build heterogeneous processing pipelines that leverage the best tools from each ecosystem.

NiTransforms emerged from the NiBabel project (specifically, PR #656) [@nibabel-pr656] as a dedicated tool for bridging these format gaps. The library implements comprehensive I/O capabilities for transform files from each major package, with careful attention to coordinate system conventions (particularly the RAS+ standard used internally). By providing a Pythonic API that abstracts away the differences between formats, NiTransforms enables researchers to focus on their analysis logic rather than low-level file format details. The library also supports the BIDS X5 format specification (BEP014) [@bids-x5] (BIDS Extension Proposal 14), which aims to establish a standardized vendor-neutral format for storing spatial transforms alongside neuroimaging datasets.

## Key Features

### Multi-Format Transform I/O

NiTransforms can read and write transformation files from AFNI, FSL, FreeSurfer (LTA format), ITK/ANTs, and SPM. The library automatically handles the coordinate system conversions required to transform between the different conventions used by each package. For example, a 4×4 affine matrix stored in FSL's matrix format can be converted to an ITK-style transform or a FreeSurfer LTA file with a single line of Python code. This bidirectional conversion ensures that transformations generated by any supported package can be applied accurately using any other package's tools.

### Affine and Nonlinear Transforms

While the library excels at handling [[linear]] (affine) transformations—including rigid-body, similarity, and full affine registrations—it also supports nonlinear transformations through displacement fields. Nonlinear transforms are typically represented as 3D vector fields stored in NIfTI format, where each voxel contains a displacement vector indicating where to sample from in the moving image. NiTransforms provides the `DisplacementsField` class for reading and writing these dense deformation fields, enabling support for warping fields generated by nonlinear registration tools like ANTs' symmetric normalization (SyN) algorithm.

### Image Resampling

The library includes a `resampling` module that provides functions for applying transformations to neuroimaging volumes. The `apply()` function takes a transformation object and a moving image, resampling the image onto the reference image's grid using the specified interpolation order. Support for different interpolation methods (nearest neighbor for labels, trilinear for continuous data, sinc for high-quality resampling) ensures that the library can handle both volumetric data and segmentations/parcellations.

### Obliquity Handling

A particularly subtle challenge in neuroimaging registration is handling oblique datasets—images whose acquisition planes are not aligned with the cardinal axes. Different packages handle obliquity in different ways: some store the obliquity information in the affine matrix itself, while others store "deobliqued" affines separately. NiTransforms carefully tracks the relationship between the moving and reference image affines to ensure that transforms are correctly interpreted even when the underlying data has oblique geometry, which is particularly important for legacy datasets acquired with tilted head angles.

### BIDS X5 Support

Recent versions of NiTransforms (25.0.0+) include experimental support for the X5 transform format specified in BIDS Extension Proposal 14 (BEP014) [@bids-x5]. X5 is an HDF5-based format designed to provide a standardized, vendor-neutral way to store spatial transforms alongside BIDS-compliant datasets. The format can represent both linear and nonlinear transforms, includes fields for Jacobian determinants and metadata, and supports both volumetric and surface-based transformations.

## Relationship to TVB

While NiTransforms is not specifically designed for [[whole-brain|whole-brain modeling]], it plays an important role in the preprocessing pipelines that prepare neuroimaging data for computational models. [[the-virtual-brain]] (TVB) and related whole-brain simulation frameworks require [[structural-connectivity]] matrices derived from diffusion tensor imaging (DTI) or probabilistic [[tractography]], as well as anatomical segmentations that define brain regions. These processing [[steps]] typically involve multiple registration operations—registering diffusion images to T1 scans, registering T1 scans to standard space templates, and applying inverse transforms to project parcellations into native diffusion space. NiTransforms can serve as a utility within TVB preprocessing workflows, particularly when combining data processed with different software packages (e.g., FreeSurfer for cortical reconstruction and FSL for subcortical segmentation). The library's ability to handle complex transform chains and coordinate system conversions helps ensure that [[connectivity]] estimates are accurately mapped between spaces.

## Related Software

- [[nibabel]] — NiTransforms originated as a feature branch of NiBabel and shares design philosophy; the two libraries remain closely integrated
- [[nilearn]] — A high-level machine learning library for neuroimaging that includes registration utilities; can use NiTransforms for transform handling
- [[fsl]] — UK neuroimaging analysis suite; NiTransforms can read and write FSL FLIRT transform files
- [[afni]] — Analysis of Functional NeuroImages; NiTransforms supports AFNI's transform matrix formats
- [[freesurfer]] — FreeSurfer's cortical reconstruction suite; NiTransforms reads and writes LTA transform files
- [[ants]] — Advanced Normalization Tools; NiTransforms supports ITK HDF5 transform formats
- [[spm]] — Statistical Parametric Mapping; NiTransforms can convert SPM affine transforms
- [[bids]] — BIDS X5 format for standardized transform storage
- [[nipype]] — Neuroimaging processing pipelines; NiTransforms integrates with nipype workflows for heterogeneous processing chains
- [[nifti]] — The NIfTI file format used for storing both image data and (in some cases) transformation parameters
- [[templateflow]] — Template and atlas repository; often used together with NiTransforms for standard space operations
